How it sees

Every time the engine asks the network a question, the network gets 298 numbers: what this player knows at that moment, plus what is being asked. It answers with 34 numbers: a score for each card (or Sentry option) and one for "pass"; only the legal answers count.

The 298 inputs

turn2actions left (÷ 3), whether it is my turn (Militia discards happen on theirs)

about33the card the question is about (e.g. the card Sentry revealed)one-hot

The first 175 are az-v1's features exactly (az_features in az-v1/c/az.c); the rest are new, because this network also plays the action phase, where the hand matters.

What it does not see

The order of its own draw pile, the opponent's hand, the opponent's draw pile: the engine computes the features from the player's own view, and the order of the draw pile never enters them (only its contents, which a careful human player can count too). Unlike az-v1's search it never imagines hidden cards either: it has no search at all.

Exactly the same inputs as rl-v1, so the only difference between the two projects is how training starts. The test tests/test_core.py checks that the C forward pass and the PyTorch one agree, and that GA seats in this engine replay az-v1's games exactly.

An example

Turn 6, the opponent just played Militia, I hold Copper, Copper, Estate, Silver, Smithy. The question: "Militia discard" (one of the 22 kinds), asked twice in a row. Inputs: my hand (Copper ×2, Estate, Silver, Smithy), "my turn" = 0, actions = 0. At iteration 0 the random network is as likely to discard the Smithy as the Estate. Nobody tells it that Estates are useless in hand: it has to find out from thousands of games in which keeping the Silver and the Smithy led to more wins.
