Lessons

What this project and earlier ones taught. Newest first.

From this project

  • Give the network the arithmetic. 115 helper inputs (the next hand's expected coins and odds of $5/$6/$8, expected +Actions/+Buys, expected VP gain, and what one more copy of each card would change) were added to a network that had been flat for 400 iterations. Within 30 iterations it went from 36–38% to 40–41% head to head against rl-v1 and from 55% to 60% against az-v1, and set its best score against the GA base (74.0%). The network had all the raw counts before; computing hypergeometric odds from them was apparently too much to learn.
  • Add inputs without starting over. New inputs with zero weights (and Adam's state padded the same way) leave the network's play exactly as it was (checked on 20 games); training then decides what they are for.
  • A crash in a worker hangs the whole pool. A table sized for 5 cards overflowed when a hand held 6 (after the opponent's Council Room); the C code died with "stack smashing" and Python's process pool waited forever. With three runs and a full swap it first looked like a memory problem. Stress-test new C code on thousands of random games before training on it.
  • More exploration did not avoid the money style. A second run from zero (z2) with five times the entropy bonus early and the kingdom curriculum played exactly like z1 at iterations 100 and 150.
  • Self-play from zero finds a style early and then keeps it. By iteration 250 (about 40 minutes) it played money plus attacks: Witch, Militia, Bandit, Gardens, about 0.5 actions per turn. 600 iterations later it still did, while rl-v1, which started from the GA genome's equally plain style, slowly turned into an engine player (Sentry, Laboratory, Poacher, Market: 1.6 actions per turn) and beats it 65% of the time. A style that pays off only once you play it well (a Village is a wasted buy until you chain actions) is hard to find by trying single changes.
  • Check the mechanics, not just the score. A homepage table showed Village bought in 0% of games, which could have been a bug. Tests now check every card's +Cards/+Actions/+Buys/+$ and that a player is really asked again after a Village or Market (tests/test_vanilla.py); the trained net uses a second buy as often as the GA genome. Not a bug: a strategy choice.
  • More exploration noise did not change the style. Neither a higher learning rate (1e-3) nor a four times larger entropy bonus moved the goal check or the actions per turn within 50 iterations.
  • A teacher is not needed to get off the ground. rl-v1's lessons said that starting RL from a random network "would have spent hours relearning what the genome already knew". The first (aborted) start of this run showed the opposite for the basics: from random weights, self-play alone went from 0% to 45% against Big Money and 20% against the GA genome in 9 iterations (about two minutes), never having played either. Whether it gets past the teacher in the end is what this run is for.
  • Memory, not CPU, limited the start. Random players make long games with many decisions; 3,000 such games per iteration (as in rl-v1) ran an 8 GB laptop out of memory. 1,500 games per iteration fit.

From rl-v1 (this project's parent)

  • You can only beat what you practise against. rl-v1 tied az-v1 head to head until az-v1 joined its league; then it won 55%, and after 2,200 iterations 72%. Here the earlier models join in stage 3.
  • Speed is a feature. 3 ms per game inside the C engine, against 460 ms for az-v1's search: millions of practice games on a laptop.
  • Confirm once, on games never used, with the rival on the same games. This project has its own never-used confirmation set (experiments/confirm.py, a new seed), for the end.

From az-v1

  • Keep one number on data the model never trained on. Here: the evaluation against the GA genome and the bots during stage 1, which the network never trains against, and the win estimate's error on fresh games.
